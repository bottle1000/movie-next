# 비밀번호 공백 차단: 사용자 직접 검증

2026-10-19 사용자 제출 화면 3장과 입력·조회 순서의 명시 확인을 연결한 새 실행 기록입니다. 지원자가 조작·캡처했고 AI는 자료를 대조했습니다.

| 항목 | 기록 | 근거 |
|---|---|---|
| 이메일 | qa-space@example.com | 입력 화면·SQL 모두 동일 |
| 이름 / 생년월일 | qa-space / 2000-01-11 | 입력 화면 |
| 비밀번호·재확인 | `Aa1! bbb` 모두 동일 | 사용자 명시 확인; 화면은 마스킹 |
| 입력 조건 | 8자, 대·소문자·숫자·특수문자 충족, 느낌표 뒤 공백 한 칸 | 확인한 테스트 문자열 |
| 기대 | 가입 차단·회원 미생성 | 공백 금지 안내 기준 |
| 실제 화면 | 입력 중 유효하지 않음 안내, 제출 후 공백 없이 8~64자 등의 조건 안내 | UI01·UI02 |
| 가입 시도 후 DB | 해당 이메일 member_count=0 | DB01 + 사용자의 조회 순서 확인 |
| 판정 | 이번 입력 조건의 기대결과 일치 | 입력 기록·오류 화면·DB 결과 연결 |

가입 전 SQL은 확보하지 않았습니다. 전후 SQL 모두 0이라고 쓰지 않습니다. 실제 입력 문자열은 스크린샷으로 확인한 것이 아니라 사용자의 명시 설명으로 기록합니다. 가입 시도 후 회원이 존재하지 않는 결과를 확인했으며 서버 직접 요청을 따로 실행한 것은 아닙니다. 과거 공백 포함 비밀번호의 가입·재로그인 성공을 입증하는 자료가 아닙니다. 기존 35건에 합산하지 않습니다.

## 별도 UI 관찰 C03

UI02에서 두 비밀번호 입력칸에 안내 문구가 표시되어 비어 있는 상태인데도 초록색 ‘비밀번호가 일치합니다.’가 남아 있습니다. 입력 유효성과 두 값 일치 여부는 별개이므로 UI01에서 두 안내가 동시에 표시되는 것만을 오류로 보지 않습니다. UI02의 빈 입력 상태에서 유지되는 일치 안내를 별도 관찰 사항으로 기록합니다.

기대 동작 제안: 비밀번호와 재확인 칸이 모두 비어 있을 때 일치 성공 안내를 숨깁니다. 제안한 기준이며 기존 명세가 있었다고 소급하지 않습니다. 이번에 코드를 수정하지 않았고 수정 후 검증도 없습니다. 기존 발견 결함 3건에 추가하지 않습니다.

## 포트폴리오 반영 문장

공백을 포함한 8자 비밀번호를 두 입력칸에 동일하게 입력해 가입을 시도했습니다. 공백 금지 오류 안내와 동일 이메일의 회원 수 0을 대조해 가입 차단 결과를 확인했습니다. 입력값은 직접 수행 기록으로, 제출 후 동작과 DB 결과는 캡처로 연결했습니다.
